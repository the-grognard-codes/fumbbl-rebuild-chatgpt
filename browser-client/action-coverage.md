# Supported browser actions and skills (M3c)

The supported scope remains BB2025 catalog `bb2025-human-2026-09-08.1`, preset
`human-exhibition-1150`, and its frozen Human rosters. All six positions (lineman,
halfling, catcher, thrower, blitzer, ogre), seven purchasable skills and captain Pro
remain selectable. This inventory covers their reachable action and decision
families. No catalog content was added or removed. The authoritative engine owns
rolls, modifiers, eligibility, injuries, resources and transitions.

## Rules adjudications and exclusions

The accepted external reference is Blood Bowl Base BB2025, consulted 2026-09-10:
[game rules](https://bloodbowlbase.ru/bb2025/core_rules/the_game_of_blood_bowl/) require a standing teammate with tackle zones for hand-off;
[skills](https://bloodbowlbase.ru/bb2025/core_rules/skills_and_traits/) specifies Pro's 3+ test and forbids another reroll source on the original die after a Pro attempt.
The native BB2025 RollMechanic uses 3+, despite an older Pro class comment saying 4+.
The adapter recognizes BB2025's SINGLE_DIE_PER_ACTIVATION source mapping for Pro
block dice. It does not expose legacy compound Pro/TRR options or the desktop
HAND_OVER ANYONE target mode. These are adapter restrictions to authoritative
behavior, not changes to the rules engine or starter content.

Punt, Bombardier, Kick, On the Ball, special leaps, chainsaw, bribes, inducement
stars, Bloodlust, Animal Savagery and other noncatalog skills/choices are outside
this preset. No purchasable catalog item depends on their prompts. Automatic
catch, trait, armor and injury processing is not presented as a new user choice.

The inventory and review found no uncovered action or prompt family in this
declared scope. M3d adds [drives, halves, results and replay](results-replay.md). Cleanup
and durable in-progress JVM restart recovery remain later M3 work; completion
acceptance is recorded in the linked M3d evidence. Same-JVM reconnect is supported. Synthetic
states and deterministic dice exist only in tests, never the product contract.
